## Rules

1. **Endpoint and credentials come from the environment only**; pass them to `boto3.client("s3", endpoint_url=..., aws_access_key_id=...,
   aws_secret_access_key=..., region_name=...)`. No credential files or default keys in containers.
2. **Path-style addressing for RustFS/MinIO** (`Config(s3={"addressing_style": "path"})`); virtual-hosted style needs wildcard DNS.
3. **Checksums:** `Config(request_checksum_calculation="when_required", response_checksum_validation="when_required")`: recent boto3
   versions add trailing checksums that some S3-compatible stores reject.
4. **boto3 is synchronous:** in `async def` wrap every call with `asyncio.to_thread` (the adapter's `_run`), or use `aioboto3`. Never call
   boto3 directly on the event loop.
5. **Timeouts and retries:** `connect_timeout`, `read_timeout`, `retries={"max_attempts": 3, "mode": "standard"}`.
6. **Keys:** `<domain>/<yyyy>/<mm>/<id>.<ext>`, lower-case, no leading slash, no raw user strings; set `ContentType` on write; keep the
   keys you need in PostgreSQL (do not depend on listing).
7. **Errors:** `ClientError` code `NoSuchKey`/`404` maps to `ObjectNotFoundError` (a typed exception ending in `Error`, PEP 8); wrap the rest;
   never return SDK text to clients.
8. **Large objects stream:** `get_object(...)["Body"]` with `iter_chunks()`, `upload_fileobj`/`download_fileobj` (multipart); no `read()`
   of multi-GB bodies. Bound lists with `MaxKeys` and the continuation token.
9. **Buckets are provisioned by the platform;** `ensure_bucket()` is for tests and local setup. Health: `head_bucket` is the `s3` check of `/healthz`.
10. Unit tests may use `moto[s3]`; the integration run (`-m integration`) proves the real store (round trip, list, missing key).
