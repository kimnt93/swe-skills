# Rationale template

## Usage

The 2–3 call sites the consumer will write (request and response, event in, the hook in a
component, the notebook cell), before the types.

## Shape

The types and how data flows through the signatures. The load-bearing decisions, and which
invariants the types enforce.

## Synthesis decision

Which sketch became the base and why; what was taken from the other.

## Rejected alternatives

At least one concrete alternative shape and the one-line reason it lost.

## Risks and open questions

What could make this shape wrong, and how you would notice.
