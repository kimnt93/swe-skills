# Skill reference

Every skill of the plugin, from its own `SKILL.md`. Invocation, with the default plugin name `swe` (replace it with your `PLUGIN_NAME`):

| Harness | Router | Another skill |
|---|---|---|
| Claude Code | `/swe <task>` | `/swe:<skill> <task>` |
| oh-my-pi | `/skill:swe <task>` | `/skill:<skill> <task>` (`/skill:swe/<skill>` on a name clash) |
| Codex | `$swe:swe <task>` | `$swe:<skill>` |
| Hermes and others | skill `swe` | skill `swe-<skill>` |

Agents load skills by their descriptions, so a plain request usually finds the right one; name a
skill when you want a specific one. What each skill does, step by step, is in [skills/](skills/README.md).

### architect

Settle types, signatures and module shape before code, by sketching at least two designs and picking one, then implement against the sketch. ### blast-radius

Find what a change could break elsewhere before it ships, beyond the diff, and prove the one fact it is safe because of by running code. Use for a small-looking change to shared code, a config, a schema, a message format, an API response, or a dependency bump.

- **Invoke:** `/swe:blast-radius`
- **Detail:** [process.md](skills/process.md#blast-radius) · **Source:** [SKILL.md](../src/skills/blast-radius/SKILL.md)

### changelog

Keep change logs true across a project of several GitHub repos - every repo has a CHANGELOG.md with an Unreleased section and every pull request that changes behaviour adds its entry before merge; the manager keeps a project change log directory (changelog/project.md and one file per repo) that records each merged PR and the cross-repo story. Use when opening, reviewing or fixing a PR that needs a change log entry, when the merge gate says the changelog is missing, when cutting a release, or when asked what changed in a repo or in the project.

- **Invoke:** `/swe:changelog`
- **Detail:** [process.md](skills/process.md#changelog) · **Source:** [SKILL.md](../src/skills/changelog/SKILL.md)
- **References:**

- **Assets:** `CHANGELOG.template.md`

### ci-fixer

How an agent fixes a pull request whose CI check is red: read the failing check's log, reproduce it locally, fix the cause on the same branch within the card's files, prove it with make verify, and stop when the fix would change the check, the tests' meaning or files outside the card. Use whenever a required check on an open PR fails, flaky or not.

- **Invoke:** `/swe:ci-fixer`
- **Detail:** [process.md](skills/process.md#ci-fixer) · **Source:** [SKILL.md](../src/skills/ci-fixer/SKILL.md)

### correct

Find the mistakes agents keep repeating in a repo and make each one impossible: architecture first, then types, then a lint or check whose error names the fix, then a test, docs last. Use when you or the human correct the same mistake twice.

- **Invoke:** `/swe:correct`
- **Detail:** [process.md](skills/process.md#correct) · **Source:** [SKILL.md](../src/skills/correct/SKILL.md)

### deslop

Clean a diff before review: delete comments that restate code, dead code, debug output, unreasoned lint suppressions and defensive checks for impossible states, and make the PR text plain. Use before every review and commit, and when asked to tighten or unslop changes.

- **Invoke:** `/swe:deslop`

### formal-verify

Formally check the code where a bug costs the most and tests reach the least: an order or position state machine, retries around a commit, concurrent balance updates, a parser, Rust unsafe code. Picks the tool (TLA+, property-based tests, Kani), proves the property can fail, and keeps the check true to the code as it changes. Use for money-path state machines and races, or after merges that touched verified code.

- **Invoke:** `/swe:formal-verify`
