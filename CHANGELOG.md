# Changelog

Versions follow semver: a new skill or a rule a skill newly enforces is a minor version; wording
and fixes are a patch. `make publish` refuses a version without an entry here.

## 3.5.0

- Context limits in one place (`context:` in `fleet/models.yaml`): Claude models compact at 350k
  (300 to 400k band), every other model at 245k of a 272k window (the price step). `fleet context
  show | apply` writes Claude Code (`autoCompactWindow`), Codex and oh-my-pi
  (`compaction.thresholdTokens`); `fleet lane` exports `CLAUDE_CODE_AUTO_COMPACT_WINDOW` per card;
  Hermes profiles get `model.context_length` and `compression.*` by their model.
- `fleet sync` and the Hermes slash command `/sync`: log in once on the default profile; the sync
  copies provider API keys (never messaging tokens) to every profile, applies models, context limits
  and skills, reports a profile login that hides the default's, and takes under a second when nothing
  changed. `fleet bootstrap` installs `/sync` and applies the context policy.
- `docs/context-and-sync.md`.

## 3.4.0

- The default plugin name is `swe`: the entry command is `/swe`, skills are `/swe:<skill>`.
- Docs: `docs/` has getting-started, setup A (Claude Code on a Claude subscription), setup B
  (oh-my-pi), usage, the recommended setup, the architecture, agents and skills, and a skill
  reference generated by `scripts/gen_docs.py` (`make docs`; `make test` fails when it is stale).
- Every harness the installer knows (31, from Claude Code, Codex and oh-my-pi plugins to the skill-directory
  harnesses) is tested in a scratch home at user and project scope, and documented in the generated
  `docs/harnesses.md`.
- The `plans/` directory is gone: the build, process skills, enforcement, fleet and publish plans are
  implemented and covered by tests; the steps that need you are `docs/runbooks.md`; the decisions are in
  `docs/architecture.md`.
- `fleet/examples/models.claude-only.yaml` and `models.omp-only.yaml`: one-lane setups
  (`FLEET_MODELS=... fleet bootstrap`); a single lane may review itself at tier `top`.

## 3.3.0

- Projects on Hermes: the root `default` profile manages projects and routes requests; one
  `pm-<project>` manager per project (`fleet project add | list | sync`, `fleet/projects.yaml`)
  orchestrates issues and cards and never edits code; the lanes are shared. Managers split work
  themselves (auto-decompose off).
- New `github` skill: branch → small Conventional Commits → PR (`Closes #issue`) → the gate → `main`,
  with the commands, what to write, and the checks after each submit; `pr_lint.py` enforces the
  submit rules (branch, title, body, issue, size, scope, no secrets).
- New `project` skill: the project's documents (`ARCHITECTURE.md` as the contract, ADRs, CHANGELOG,
  RUNBOOK), PR and issue templates, labels, and `setup_repo.sh` (squash only, protected `main`).
- Architecture enforced: Go `archcheck` and Python `lint-imports` contracts in `make verify`; the
  py-code template gained the missing `api/__init__.py`.
- `fleet merge --approved`: the manager merges when the human says so (any risk, still the verified
  SHA and green checks); merges delete the branch. Verdicts are comment reviews (agents share the
  human's GitHub account).
- Docs: `docs/architecture.md` (the solution design) and `docs/agents-and-skills.md`.

## 3.2.0

- Stack priorities in the router: Go/Fiber for APIs and services, Python for ML and data, Rust for
  performance, Next.js or Vite + React + TypeScript for frontends; the language skills say their role.
- New `ts-code` skill with tested templates: Vite + React + TS (React Query, Vitest, Playwright) and
  Next.js App Router (standalone, `/healthz` in the API contract shape); `Dockerfile.nextjs`,
  `Dockerfile.vite` + `nginx.spa.conf`; frontend sections in `api-contract`, `deployment-setup`,
  `service-errors` and `verify-create`. `tests/frontend_test.sh` runs install, typecheck, lint, tests,
  build, Playwright (`--e2e`) and the images (`--docker`).
- New `py-code` `ml` reference: time-ordered splits, no look-ahead, model cards, serving, ML tests.
- Every skill copied from pstack rewritten short and concrete for this stack; new skills `how`, `why`,
  `deslop`; new router playbooks `multi-phase`, `profiling`, `babysit`, `figure-it-out`; new
  principles `minimize-reader-load`, `redesign-from-first-principles`.
- Fixed: process skills had `disable-model-invocation`, which stopped the router from running them.

## 3.1.0

- The plugin's name comes from the build (`PLUGIN_NAME`, default `kim`); the router skill carries
  the same name, so the entry command is `/kim`.
- Org-specific values are build settings: `PLUGIN_DOMAIN` (hosts and URLs in templates),
  `PLUGIN_OWNER`, `PLUGIN_HOMEPAGE`; private values go in a git-ignored `plugin.local.env`.
- New process skills: `architect`, `verify-maintain`, `ketchup`, `reflect`, `formal-verify`
  (create and maintain), `replay-test` (with a self-tested replay script); new router playbooks
  `hillclimb` and `migration`.
- Enforced, not just written: Go data structs (`go-code/scripts/structcheck`: no pointers, no
  `omitempty`), Python imports (ruff `TID251`: no pydantic, no pandas), `make verify` as a required
  CI job in the `deployment-setup` workflow template.
- Claude Code subagents `<name>:worker` and `<name>:adversary`, with models taken from
  `fleet/models.yaml`.
- `fleet` command: every agent level (board, lanes, workers, reviewers, subagents, omp roles,
  board settings, autopilot) in `fleet/models.yaml`; `fleet bootstrap` builds the Hermes side
  from it; `fleet merge` is the autopilot guard.
- Removed: the trading alpha metrics skill.
